# 项目技术报告 —— A股历史形态匹配研究看板

> 本工具仅对 A 股历史公开数据做统计研究：输出为形态特征匹配度分数，表示当前个股与
> 历史上升段启动样本的特征相似程度，不代表未来表现，不构成任何形式的操作指引。
> **历史数据不等于未来表现，市场有风险，研究需谨慎。** 仅限本地运行，请勿部署到公网。

## v1.1 规则详解（总分 100）

### 一、基础过滤（不满足直接剔除，不计分，与 v1.0 保持一致）

| 序号 | 规则 | 参数 |
|------|------|------|
| 1 | 剔除 ST / *ST / 退市整理股票 | 名称关键词 `ST`、`*ST`、`退` |
| 2 | 上市天数不足 | `< 365` 自然日剔除 |
| 3 | 停牌 / 无成交 | 当日成交额 `<= 0` 剔除 |
| 4 | 剔除北交所 | 仅保留 60 / 68 / 00 / 30 代码前缀 |

### 二、模块一：核心形态匹配分（0-50）

| 序号 | 指标 | 条件 | 分值 |
|------|------|------|------|
| 1 | MACD(3,6,3) | 金叉（DIF > DEA）且红柱 > 0 | 15 |
| 2 | KDJ(9,3,3) | 金叉（K > D）且 J < 100 | 12 |
| 3 | 量能达标 | 成交量 > 1.3 × 近5日均量 | 8 |
|    |          | 成交量 > 2 × 近5日均量（叠加） | +5（量能满分 13） |
| 4 | 换手率健康度 | 当日换手率 ∈ [3%, 15%] | 5 |
| 5 | 横盘形态 | 近40个交易日 最高价/最低价 ≤ 1.8 | 5 |

技术指标口径：MACD 红绿柱 = 2 × (DIF − DEA)；KDJ 采用通达信 SMA 平滑口径；
价格为前复权。

### 三、模块二：筹码与基本面加分（0-20）

| 序号 | 指标 | 条件 | 分值 |
|------|------|------|------|
| 1 | 筹码集中度 | ≤ 18% | 3 |
|   |            | > 20%（在 3 分基础上再加 5 分） | 至满分 8 |
|   |            | 介于 18%-20% / 数据缺失 | 0 |
| 2 | PE 行业分位 | 低于所属行业 30% 分位 | 6 |
|   |             | 行业 30%-70% 分位 | 3 |
|   |             | 高于 70% 分位 / 缺失 | 0 |
| 3 | 5日涨幅健康度 | 近5日涨幅 ∈ [5%, 20%] | 6 |
|   |               | 区间外 / 缺失 | 0 |

**PE 行业分位数据口径**：免费公开接口无「行业 3 年历史 PE 序列」，
当前采用**同行业当日截面分位**近似（同一行业分类下全部有效 PE>0 的个股
参与排序；行业内有效样本数 < 5 时该项计 0 分，参数
`config.PE_MIN_INDUSTRY_PEERS`）。PE 为市盈率 TTM（腾讯行情），
亏损股（PE ≤ 0）不参与分位计算。

**筹码集中度**来自东财筹码接口（可选抓取）；本机网络不可达时该项计 0 分，
不影响其他项（设计内降级）。

### 四、模块三：行业与板块加分（0-30）

| 序号 | 指标 | 条件 | 分值 |
|------|------|------|------|
| 1 | 板块属性 | 创业板(30) / 科创板(68) | 8 |
|   |          | 沪主板 / 深主板 | 0 |
| 2 | 热点行业加成 | 所属行业命中热点名单 | 22 |
|   |              | 未命中 | 0 |

**热点行业名单**：`config/hot_industries.json`，可自由编辑，保存后下次
扫描或重算自动生效（无需重启服务）。行业名支持前缀匹配，例如
`半导体` 可命中以 `半导体` 开头的行业名称。

### 五、附加展示字段（仅展示，不参与打分）

- **MACD 红柱相对前高收缩**：当日红柱 > 0、回看 20 个交易日（不含当日）
  红柱最大值 > 0、且当日红柱 < 前高。为历史见顶相关指标，仅供研究。
- KDJ-J 值、当日换手率、近40日最高/最低价、PE(TTM)、近5日涨幅等。

### 六、宏观参考面板（仅展示，不参与个股打分）

- 国内：上证指数、深证成指、创业板指、科创50
- 海外/港股参考：纳斯达克、标普500（隔夜）、恒生指数（当日）
- 行情源不可用时自动回退最近一次成功快照（本地缓存），并标注数据时间。

## 数据源与降级策略

| 数据 | 主源 | 备源 | 降级行为 |
|------|------|------|----------|
| 全市场快照 | 东财 | 新浪分页列表 | 部分页失败时使用已获取部分 |
| 日K（前复权） | 东财（熔断保护） | 腾讯 fqkline（多镜像） | 逐股失败跳过 |
| 行业分类 | 申万一级行业成分（31 个） | 东财行业板块 → 新浪行业板块 → 北交所证监会行业 | 依次补缺，经别名归一化后仍无法归类的丢弃 |
| PE(TTM) | 腾讯批量行情 | — | 失败时分位项计 0 分 |
| 筹码集中度 | 东财 | — | 失败计 0 分 |
| 国内指数 | 东财（首个分组失败即熔断） | 腾讯 | 失败回退本地缓存快照 |
| 海外/港股指数 | 腾讯 | — | 失败回退本地缓存快照 |
| 市场资讯 | 东财全球快讯 | 同花顺 → 财联社 → 富途牛牛 → 新浪财经 | 单源超时/失败切换下一源；全部失败返回 `available=false` |

### 行情源的「无成交额」陷阱（重要）

腾讯 fqkline 返回的日 K **不含成交额**。若全量刷新时用腾讯源重建了当日 K 线，
`amount` 字段会为空，而基础过滤第 3 条（当日成交额 > 0，用于剔除停牌）会因此
把大量正常个股判为停牌剔除——本项目实测曾出现候选池从 4870 只骤降到 848 只。

修复分两处：

1. `sync_spot_day()` 取代原 `append_spot_if_missing()`：当日 K 线已存在时不再直接跳过，
   而是**回填 `amount` / `turnover_rate` 空字段**；
2. `compute_stock()` 增加快照成交额兜底——K 线成交额为空时改用行情快照的成交额判定。

## 离线重算说明

K 线缓存保留时，可仅重算分数而不重新拉取行情：

```bash
python scripts/rescore_v11.py
```

适用于修改热点行业名单或调整打分参数后快速刷新候选池。
重算时换手率取自 K 线缓存最后一天；PE 为当前实时值。

### 个股明细抽屉的渲染约束（重要）

明细图采用 ECharts **多 grid 布局**（K 线 / 成交量 / MACD / KDJ 四个绘图区）。
在该布局下，`xAxis` 与 `yAxis` 必须**同时显式声明 `gridIndex`**：

```js
xAxis: [0, 1, 2, 3].map((i) => ({ type: "category", data: dates, gridIndex: i })),
yAxis: [0, 1, 2, 3].map((i) => ({ scale: true, gridIndex: i })),
```

若仅 `yAxis` 指定而 `xAxis` 缺省，ECharts 会把全部 x 轴挂到 0 号 grid，
其余 grid 出现「有 y 轴无 x 轴」的错配，渲染期抛出
`Cannot read properties of undefined (reading 'type')`。
该异常发生在 `setOption` 内部，会被外层 `try/catch` 捕获，
前端只表现为一句「明细数据加载失败」，排查时容易误判为接口问题。

> 排查经验：接口返回 200 且字段完整、浏览器无未捕获异常时，
> 应怀疑渲染层异常被 `try/catch` 吞掉——可在控制台手动调用渲染函数并打印 `e.stack` 定位。

### 详情接口返回结构

`GET /api/pool/{code}?days=120` 同时返回三类内容：

| 字段 | 说明 |
|------|------|
| `dates` / `kline` / `indicators` | 前复权日 K 与 MACD、KDJ、MA5/10/20/60 序列 |
| `profile` | 代码、名称、板块、行业（申万一级） |
| `score` | 综合匹配分、三模块得分与逐项命中明细（`breakdown` / `metrics` / `display`） |

档案与得分随详情一并返回，抽屉展示不依赖列表页缓存，口径始终一致。

### 缓存控制

首页返回 `Cache-Control: no-cache`，静态资源带版本号（`app.js?v=1.8.0`）。
两者配合可确保升级后浏览器立即加载新版脚本，避免旧版脚本产生接口路径
或字段结构不匹配导致的「功能莫名失效」。

> 升级前端时**必须同步改 `index.html` 里的版本号**，否则浏览器会继续用旧脚本命中新接口。

## 页面结构改造实现（v1.8.0）

### 改造边界

只动前端四个文件（`app/static/index.html` / `app.css` / `app.js` / `i18n.js`）。
后端（`app/routers/*`、`scoring.py`、`backtest/*`、`report.py`）与数据库**零改动**，
17 个接口路径逐条校验未变；打分逻辑、数据口径、请求时机与既有交互全部保持原样。

### 标签页机制

- 结构：按钮 `.tab[data-tab]` ↔ 面板 `.tab-panel#panel-{key}`，键集合
  `TABS = ["pool", "backtest", "report", "market", "settings"]`，默认 `DEFAULT_TAB = "pool"`
- `switchTab(name)` 只做三件事——切 `.is-on` 与 `aria-selected`、切 `panel.hidden`、按需重绘图表；
  **不发起任何数据请求**（数据仍按原有时机加载并缓存）
- 深链与历史：`currentTabFromHash()` 读 `location.hash`，`switchTab` 内 `history.pushState` 写回，
  `popstate` 支持浏览器前进 / 后退，非法 hash 回落默认页
- 窄屏：`.tab-list` 与 `.nav-menu` 同源（都带 `data-tab`），`≤900px` 由媒体查询切换显隐，
  点选后 `closeNavMenu()` 自动收起
- 图表按需重绘：`redrawTabCharts(tab)` 只在切到含图表的页面时重绘该页图表，
  再于 `requestAnimationFrame` 内统一 `resizeCharts()`

### 三个必须处理的细节

1. **`display` 会覆盖 `[hidden]`**：若样式里给面板写了 `display: block`，`hidden` 属性即失效。
   因此显式补上 `.tab-panel[hidden] { display: none }`；语言切换页的徽标同理需 `.x[hidden] { display: none }`。
2. **隐藏容器不能 resize**：`display: none` 下图表容器的 `clientWidth / clientHeight` 均为 0，
   此时调 `resize()` 会把画布压成 0 宽且不会自行恢复。`resizeCharts()` 先判可见性再调用：

   ```js
   const dom = typeof inst.getDom === "function" ? inst.getDom() : null;
   if (!dom || !dom.clientWidth || !dom.clientHeight) continue;
   inst.resize();
   ```

   切换标签后等一帧再 `resize`，确保新页容器已完成布局。
3. **简报预览的「已加载」判断不能用 `null` 作哨兵**：`state.runId` 的初始值与
   「尚未取到批次」同为 `null`，若写成 `if (!force && state.repFrameRunId === state.runId) return;`，
   首次进入简报页会被误判为已加载，`frame.src` 恒为空、提示层停在「简报加载中…」。
   现改用独立布尔位 `state.repFrameLoaded` + 字符串化批次快照 `state.repFrameKey`
   （`state.runId == null ? "" : String(state.runId)`），并补回归测试锁死该场景。

### 功能图标

不使用 emoji 或符号字符作功能图标（渲染尺寸与基线在不同系统下不可控），统一走内联描边 SVG。
原先两处 `U+2713` 勾号已替换为 `ICON.check(size)` 生成的 SVG，`.tag-*` 由 `inline-block`
改为 `inline-flex` 以便图标与文字居中对齐。

## 市场资讯模块实现（v1.4.0）

### 定位

**只做聚合与归类**：内容为第三方公开快讯的原文标题与链接，本工具不生成、不评论、
不解读任何资讯，也不参与个股打分。前端在所有主功能渲染完成之后才异步加载资讯，
**资讯接口失败绝不阻塞候选池、筛选、导出等主功能**。

### 数据源

| 顺序 | 接口（AKShare） | 来源 | 字段 |
|------|-----------------|------|------|
| 1 | `stock_info_global_em` | 东方财富 | 标题 / 摘要 / 发布时间 / 链接（最完整，单次约 200 条） |
| 2 | `stock_info_global_ths` | 同花顺 | 标题 / 内容 / 发布时间 / 链接 |
| 3 | `stock_info_global_cls` | 财联社 | 标题（常为空）/ 内容 / 日期 + 时间（无链接，回退源主页） |
| 4 | `stock_info_global_futu` | 富途牛牛 | 标题 / 内容 / 发布时间 / 链接 |
| 5 | `stock_info_global_sina` | 新浪财经 | 时间 / 内容（无链接，回退源主页） |

抓取到目标条数（默认上限的 2 倍）即停止请求后续源；多源结果按
「标题去除非字母数字字符后取前 36 字符」的指纹去重，保留先出现（信息最完整）的一版。

### 超时保护的一个坑

单源超时不能直接写成 `with ThreadPoolExecutor(...) as pool: pool.submit(fn).result(timeout=t)`——
线程池的上下文管理器在退出时会 join 工作线程，**即使已经超时也会被卡住**，超时保护形同虚设。
本项目改用「守护线程 + `queue.Queue(maxsize=1)`」：超时后直接放弃该线程，不再等待。

### 分类规则

判定顺序：**境内市场强特征 → 海外 → 宏观 → 国内兜底**。

| 分类 | 判定要点 |
|------|----------|
| 国内资讯 | A股、沪指、深证成指、创业板指、北交所、上交所、深交所、证监会、涨停、龙虎榜、新股、解禁、两融、银行间、减持、增持、回购、中标、公告、上市公司 等 |
| 海外资讯 | 美股 / 纳指 / 标普 / 道指 / 美联储 / 港股 / 恒生 / 中概股 / 华尔街 / 美债 / 非农；海外国家与地区名、国际组织、地缘海域、海外知名公司与机构、海外地名 |
| 宏观资讯 | 央行 / 货币政策 / 社融 / CPI / PPI / PMI / GDP / LPR / MLF / 降准 / 降息 / 财政 / 国债 / 汇率 / 统计局 / 关税；以及 WTI、布伦特、LME 等大宗商品定价相关 |

两点设计取舍：

1. **境内强特征优先**：否则「美联储加息落地 A 股三大指数集体高开」会被误归为海外资讯。
2. **「中国 / 国内 / 全国」不放强特征**：它们是兜底类目，若放进强特征会抢走本应
   归入宏观资讯的央行、统计局类条目（默认兜底即为国内，无需重复声明）。

分类为**关键词启发式**，仅用于辅助浏览，不保证逐条准确，已在 README 中明示。

### 中性化过滤

为保持项目措辞规范，标题含交易指令类表述的条目整条跳过。词表存放在
`app/config.py` 的 `NEWS_BLOCK_PARTS`，与 `scripts/word_check.py` 同法，
以「前半 + 后半」片段拆分存储，避免配置文件自身被合规自检命中。
如需完整保留第三方原文，将该元组清空即可。

### 缓存与降级

抓取结果整体写入 `meta` 表的 `news_feed_cache` 键并设 30 分钟有效期；
应用启动时通过 `lifespan` 后台线程预热一次。全部源失败时接口返回：

```json
{ "available": false, "items": [], "message": "资讯暂不可用" }
```

前端渲染「资讯暂不可用」占位，模块结构保持完整，页面其余部分不受影响。

#### 预热入口的坑（v1.8.1 修复）

启动预热**不能直接以函数方式调用路由处理函数**。FastAPI 路由签名里的
`Query(...)` 默认值（如 `limit: int = Query(0, ...)`）只有在经过框架的参数解析后
才会变成真实取值；直接调用拿到的是 `Query` 对象本身，于是：

```python
cap = limit or config.NEWS_MAX_ITEMS   # limit 是 Query 对象，真值 → cap 是 Query 对象
return {**data, "items": items[:cap]}  # TypeError: slice indices must be integers...
```

异常被外层的 `try/except` 吞成一条 warning，外部表现是**每次启动都预热失败**，
首屏资讯退化为「打开页面时才现抓」，且不报错、不中断，极容易被忽略。

修复方式：把与请求参数无关的「读缓存 → 抓不到就抓一次 → 落库」逻辑抽成
`_load_or_build(conn)`，另加专用预热入口 `warm_cache()`；路由函数复用同一实现，
只保留参数解析后的筛选与截断，**对外返回结构完全不变**。

> 通用教训：任何带 `Query(...)` / `Depends(...)` 默认值的路由函数都只能由框架调用，
> 需要复用其内部逻辑时，必须把纯逻辑抽到普通函数，再让路由函数去调它。

## 中英双语实现（v1.5.0）

### 设计边界

采用**基础双语方案**：只翻译界面文案，不触碰打分逻辑、数据层与接口。
具体约定：

| 对象 | 处理方式 |
|------|----------|
| 界面文案（标题 / 按钮 / 标签 / 免责声明 / 统计说明 / 筛选选项 / 弹窗文案 / 页脚） | 全部走语言包 |
| 专业指标（MACD / KDJ / PE(TTM) / 换手率） | 中英一致，沿用国际通用写法 |
| 指数名称 | 市场通用英文名（上证指数 → SSE Composite，标普500 → S&P 500 等） |
| 行业分类 | 申万一级行业标准英文译名（31 个全覆盖） |
| 股票名称 / 代码 | **不翻译**，保持原样 |
| 市场资讯标题 | **不翻译**，英文界面保留第三方中文原文并标注「News in Chinese」 |

### 词条组织

语言包集中在 `app/static/i18n.js`，对外暴露五个方法：

```js
I18N.t(key, vars)     // 取词，支持 {name} 占位符替换
I18N.industry(name)   // 行业中文名 → 当前语言展示名
I18N.board(name)      // 板块中文名 → 当前语言展示名
I18N.indexName(name)  // 指数中文名 → 当前语言展示名
I18N.setLang("en")    // 切换语言并持久化
```

两条替换路径：

1. **静态文案**：页面元素加 `data-i18n`（另有 `data-i18n-ph` / `-title` / `-aria`
   对应 placeholder、title、aria-label），`applyStatic()` 一次性批量替换；
2. **动态文案**：渲染函数一律调用 `t()` 取词，不再出现字面量文案。

### 切换流程与重绘

```js
I18N.onChange(() => { syncLangUI(); rerenderAll(); });
```

`rerenderAll()` 用**已缓存数据**重绘宏观面板、统计卡、筛选下拉、候选池表格、
行业分布图、资讯模块与明细抽屉，**不发起任何接口请求**（验收实测切换后
`performance.getEntriesByType("navigation").length` 仍为 1，即未发生页面跳转/刷新）。
语言偏好写入 `localStorage`（键 `patternlab.lang`），刷新后保持。

### 三个容易踩的坑

1. **接口参数必须保持中文**：行业、板块的 `<option value>` 始终写入接口认识的
   原始中文值，切换语言只替换展示文本。若把 value 也翻译，筛选会全部失效。
2. **图表需要显式重绘**：ECharts 的轴标签与 series 名称不会被 DOM 文案替换波及，
   必须重新 `setOption`。同时在英文下把行业图的 `grid.left` 从 110 加宽到 205，
   否则标准英文行业名（如 Petroleum & Petrochemicals）会被容器左边缘裁切。
3. **`display` 会覆盖 `[hidden]`**：`#newsLangBadge` 需要 `display: inline-block`，
   必须补一条 `.news-lang-badge[hidden] { display: none; }`，
   否则中文界面下该标注不会隐藏。

### 测试

`tests/test_i18n.py` 直接解析静态文件文本做一致性校验，不需要浏览器环境：

- 中英语言包词条**一一对应**（不允许任何单边缺失）；
- `index.html` 的 `data-i18n*` 与 `app.js` 的 `t("...")` 引用**全部存在**于两个语言包；
- 申万一级 **31 个行业**英文译名全覆盖且不重复；
- 板块与 7 个宏观指数英文映射完整；
- 静态资源版本号统一、语言包先于 `app.js` 加载。

## 历史回测模块实现（v1.6.0）

### 定位与边界

回测模块只回答一个统计问题：**把 v1.1 打分体系原样放回历史，按分数分档后的实际表现分布是什么样的。**
它不做参数寻优、不做策略优选、不宣称任何有效性。所有输出均为历史样本的事后统计。

### 三层结构

| 文件 | 职责 |
|------|------|
| `app/backtest/data.py` | 回测专用数据层：拉取近 3 年前复权日线并落库，断点续传 |
| `app/backtest/stats.py` | 纯函数绩效统计，不依赖数据库，可单独测试 |
| `app/backtest/engine.py` | 回测引擎：滚动窗口指标预计算 → 分档 → 撮合 → 落库 |

### 数据物理隔离（重要）

回测数据**绝不复用**看板扫描所用的 `klines` 表，而是新建六张独立表：

| 表 | 内容 |
|----|------|
| `bt_klines` | 个股回测日线（前复权，独立于扫描缓存） |
| `bt_index` | 基准指数日线（沪深 300，`sh000300`） |
| `bt_runs` | 回测批次主记录（区间、参数、摘要） |
| `bt_stats` | 分档绩效统计（每组 × 每个持仓周期） |
| `bt_equity` | 累计净值序列（三组 + 基准） |
| `bt_trades` | 逐笔样本明细（观察日 / 分档 / 得分 / 入场价 / 各周期收益） |

这样做的两个理由：一是扫描用的缓存窗口只有约 276 个交易日，不足以支撑 3 年回测；
二是前复权口径以**最新交易日收盘为基准**，分次拼接会产生跳空，
因此回测数据必须一次全量拉取、独立存放，避免与扫描数据的增量更新互相污染。

### 前瞻偏差（未来函数）防御

这是回测模块最核心的工程约束，分三层落实：

1. **指标层**：`_prepare_stock()` 对每只股票的完整序列**一次性预计算**全部指标
   （MACD / KDJ / 均线 / 量能 / 振幅 / 涨幅），且每个指标都是**滚动窗口**——
   第 i 个交易日的取值只依赖第 i 日及之前的数据，不存在任何回看未来。
2. **时序层**：观察日 T 收盘后才能拿到当日完整数据，因此打分发生在 T 日收盘**之后**，
   入场必然在 **T+1 开盘价**，不存在「以 T 日收盘价入场」这一不可能实现的假设。
3. **出场层**：T+n 持仓周期以 **T+n 日收盘价**结算，与入场口径分离。

对应的测试是 `tests/test_backtest.py` 中两组互补用例：
把数据截断到第 k 日重跑，前 k 日的每格得分必须与完整数据下逐格一致；
再做反向验证——若前段结果随未来数据变化，说明存在泄漏。

### 撮合与分组口径

| 项 | 口径 |
|----|------|
| 分组阈值 | 高 ≥ 60 / 中 30–59 / 低 < 30（沿用看板分档） |
| 调仓步长 | 每 20 个交易日一个观察点（`BT_REBALANCE_STEP`） |
| 持仓周期 | 5 / 10 / 20 日（`BT_HORIZONS`） |
| 入场价 | T+1 开盘价 |
| 出场价 | T+n 收盘价 |
| 基准 | 沪深 300 指数同期净值 |
| 超额收益 | 组累计收益 − 基准累计收益 |
| 样本独立性 | 5 / 10 / 20 日三组样本**互不重叠**（同一观察点仅取一个周期） |

**剔除规则与看板基础过滤完全一致**：剔除 ST / *ST / 退市整理（按最新证券简称关键词判定）、
上市不满 365 天、当日停牌（成交额 ≤ 0）、北交所（代码前缀不在 60/68/00/30 内）。

### 为什么回测满分是 81 分

打分体系中「筹码集中度」「PE 行业分位」「换手率」三项依赖**当日截面数据**，
在历史时点不存在免费、可复现的数据源。若用当前值回填历史，等同于引入前视偏差；
若用近似值估计，则任何人复算都会得到不同结果。

因此回测口径下这三项**统一计 0 分**，`BT_SCORE_MAX = 81`。
分组阈值仍沿用 60 / 30（即按原始分档标准，不按比例缩放），
这一取舍已在研究简报的「研究局限性」一节中明示。

### 实测结果（2026-09-03 全量运行）

| 项 | 值 |
|----|----|
| 回测区间 | 2023-12-19 ～ 2026-08-12 |
| 调仓点数 | 33 个 |
| 覆盖个股 | 5009 只（剔除 ST/*ST/退市整理 200 只） |
| 样本总数 | 157,745 条 |
| 耗时 | 26.7 秒 |

| 持仓周期 | 高分组 | 中分组 | 低分组 |
|----------|--------|--------|--------|
| 5 日 | 46.19% / +0.33% | 44.40% / −0.15% | 43.28% / −0.41% |
| 10 日 | 52.75% / +2.08% | 51.21% / +1.74% | 48.28% / +1.19% |
| 20 日 | 51.63% / +2.21% | 51.64% / +2.35% | 48.09% / +1.20% |

（数值为「上涨占比 / 平均收益率」。三个周期上高分组的上涨占比与平均收益均高于低分组，
单调关系清晰；**但这只是历史样本的统计描述，不构成对未来表现的任何推断。**）

## 研究深度分析实现（v1.7.0）

### 定位与边界

四项分析（分行业回测 / 统计显著性 / 参数敏感性 / 多周期共振）**全部是对已有回测批次的二次统计**：

- 不重新抓取行情、不重算技术指标，因此与第三节回测结论**同源可对账**；
- 唯一例外是参数敏感性分析——它必须用扰动后的参数**重跑回测**，但以 `persist=False`
  运行，结果只进内存、不写 `bt_runs` / `bt_stats` / `bt_trades`，主干批次不受污染。

存放在三张独立结果表中（`bt_industry` / `bt_resonance` / `bt_sensitivity`），
均以 `run_id` 为第一主键，重复构建时先 `DELETE ... WHERE run_id=?` 再写入，保证幂等。

### 一、分行业回测

**聚合口径**。`app/backtest/industry.py` 不重新计算任何指标，而是对 `bt_trades`
做两组 SQL 聚合：

- `_aggregate_cells()`：按（行业 × 分组）算 `COUNT` / `SUM(ret > 0)` / `SUM(ret)`，
  得到样本数、上涨胜率、平均收益率；
- `_aggregate_periods()`：按（行业 × 分组 × 观察日）求等权平均收益，再用
  `stats.build_nav()` 复利累积成净值序列，由净值算最大回撤。

最大回撤必须用「按期等权聚合后的组合净值」，而不是对单笔样本收益直接累计——
后者会因为样本数量随观察日波动而失真。这与第三节分档绩效的回撤口径一致。

**占位行业的排除（一处真实缺陷）**。行业匹配失败的个股在回测明细中记为
`其他`（`scanner.INDUSTRY_FALLBACK`）。它被 `industry_universe()` 排除在行业全集之外，
但最初的聚合 SQL **没有同步排除**，于是 `covered_count`（有样本的行业数）会把
`其他` 算作一个真实行业，出现「覆盖 32 / 共 31」这类自相矛盾的覆盖率。

修复方式是把排除条件抽成 `_placeholder_filter()`，让聚合 SQL 与行业全集
共用同一份 `config.INDUSTRY_PLACEHOLDERS`，并在测试中锁定
「覆盖行业数 ≤ 行业总数」这一不变量。本机真实数据下 `其他` 恰好没有样本，
所以这个缺陷只在特定数据形态下才会暴露——这正是需要不变量测试而非
快照测试的原因。

**靠前 / 靠后行业必须互不重叠**。参与排名的行业往往远少于行业总数
（高匹配分依赖热点行业与成长板块加分，样本天然向少数行业聚集）。
若强行各取 Top5 / Bottom5，在只有 6 个行业可排名时两处会重叠 4 个，
读起来自相矛盾。因此规则改为：参与排名行业数 ≥ 2n 时各取 n 个，
否则对半拆分（前半相对靠前、后半相对靠后）。

另输出**行业集中度**（`industries_with_samples` / `top3_share` / `top_industries`），
用于在简报与看板中解释「为何参与排名的行业数少于行业总数」。

**一致性自证**。分行业结果的可信度由一个硬约束保证：把各行业的样本合并回去，
必须等于整体口径。实测 9 个格（3 周期 × 3 分组）样本数全部吻合。

### 二、统计显著性检验

**Welch t 检验**（不假设方差齐性）：

```
se² = v₁/n₁ + v₂/n₂            t = (x̄₁ − x̄₂) / se
df  = se⁴ / [ (v₁/n₁)²/(n₁−1) + (v₂/n₂)²/(n₂−1) ]     （Welch–Satterthwaite）
CI  = (x̄₁ − x̄₂) ± t_{α/2, df} · se
```

**不引入 scipy**。项目运行时依赖刻意保持 `fastapi / uvicorn / akshare / pandas` 四项，
因此 t 分布分位自行实现：双尾 p 值用正则化不完全贝塔函数

```
p = I_{ν/(ν+t²)}(ν/2, 1/2)
```

`I_x(a,b)` 用 **Lentz 连分式**（`_betacf`，max_iter=300、eps=3e-16）配合对称分支求解；
临界值 `t_{α/2,df}` 用二分法在 `[0, 1e4]` 上求根（p 关于 t 严格单调递减，二分必收敛）。

数值上以 scipy 为对照跑了 8 组随机样本（含 n=5/7 的小样本与 n=10 万/8 万的大样本）：
最大 t 误差 4.4e-16、最大 p 误差 1.4e-14、置信区间误差 1.2e-14；
`t_critical(1) = 12.706204736174694` 与 `scipy.t.ppf(0.975, 1)` 完全一致。
测试中另用 `p(t_crit(df)) ≡ α` 的往返自洽作为独立约束。

**极端 p 值不能塌缩成 0**。初始实现沿用 `stats.safe_float(v, 8)` 统一保留小数位，
对于 t = 9.5、自由度上万的情形（p ~ 1e-21）会输出 `0.000000e+00`，
看起来像「没算出来」。修复为 p 值单独按有效数字格式化：
小于 1e-12 显示「< 1e-12」，否则用 `.4g`。

**分年度稳健性**。按自然年拆分样本，逐年比较高低分组的平均收益与胜率，
统计方向一致的年份占比（单年两组样本均需 ≥ `ROBUST_MIN_SAMPLES = 100` 才计入）。
实测 10 日周期 4/4 一致、5 日 3/4、**20 日仅 2/4**——这一差异如实写入简报局限章节。

### 三、参数敏感性分析

**参数抽离**。把回测中会影响形态判定结果的参数抽为 `ScoreParams`
（MACD 三要素、量能放大倍数、量能翻倍倍数、振幅回看窗口与阈值）。
默认值全部取自 `app.config`，因此不传该对象时回测行为与 v1.6.0 **逐位一致**。

**单因子扰动**。3 组参数各 2 档，每个变体只在一个参数族内改动
（MACD 三要素视为同一族），其余保持基准，避免多因子同时变动导致无法归因：

| 参数组 | 基准 | 变体 |
|--------|------|------|
| MACD 参数 | (3,6,3) | (2,4,2) / (5,10,5) |
| 量能放大倍数 | 1.3 倍 | 1.2 倍 / 1.5 倍 |
| 近 40 日振幅阈值 | 1.8 | 1.6（更严）/ 2.0（更宽） |

**零回归验证**。引擎改造后先用 `persist=False` 以基准参数重跑一次，
与已落库批次逐项比对：12 项指标 × 9 个格**差异项数 0**、净值序列不一致数 0、
`bt_runs` 总数不变——证明改造未改变原口径。

实测 6 个变体的方向全部保持、相对基准的最大变动仅 **0.276 个百分点**
（最敏感的是 MACD 参数组），结论对参数扰动稳健。

### 四、多周期共振策略

**周线合成**。按 ISO 自然周聚合日线：`open` 取首日、`close` 取末日、
`high`/`low` 取周内极值、`volume` 取周内合计，另记录 `bars`（该周实际交易日数）。
周线指标与日线同源：MACD(3,6,3) 金叉且红柱 > 0、KDJ(9,3,3) 金叉且 J < 100。

**未来函数规避（本节最关键的实现细节）**。观察日 T 只能使用「在 T 日已经收盘」
的周线。一个自然的错误做法是取该周个股最后一个成交日作为「周线定型日」——
**停牌股会因此把尚未定型的当周周线误判为可用**，从而把未来信息带入当期。

正确做法是由**市场交易日历**判定：用基准指数日线构造
`{(ISO 年, ISO 周): 该周市场最后交易日}`，个股周线的可用日一律取市场日历值；
日历中缺失的周标记为不可用。然后再用 `bisect_right(dates, d) - 1`
取「最近一根可用日 ≤ T」的周线。

该性质由测试锁定：把日线截断到第 40 周末重算，前 40 周共振标记必须逐周一致。

**实测为否定性结果**：双共振分组在 5 / 10 / 20 日三个周期上**全面落后**单日线高匹配分组
（5 日 −0.58% vs +0.33%、10 日 +1.26% vs +2.08%、20 日 +1.41% vs +2.21%），
胜率同样全面落后。简报据实呈现该结论，并在「结果解读」中给出三点解释
（周线条件进一步缩减样本、周线确认滞后于日线形态启动、样本量差异），
同时把它列为后续可拓展方向（尝试其他共振构造方式）——
研究项目如实报告无效结果，比只报告有效结果更有价值。

### 踩坑记录

- **数据库写锁**：`bt_industry` 落库时若看板服务仍在运行，会与扫描/接口线程争抢
  SQLite 写锁并报 `database is locked`。虽然 `db.connect()` 已设 `busy_timeout=8000`
  与 WAL，长时间写事务仍应**先停服务再落库**。
- **`dict.get(k, default)` 对空列表不生效**：`rob.get('years', ['—'])[0]` 在
  `years == []` 时返回的是空列表本身而非默认值，直接抛 `IndexError`。
  凡取值后立即索引的写法都必须先判空。
- **Windows 控制台编码**：`subprocess.run(..., text=True)` 按 UTF-8 解码中文
  GBK 输出会抛 `UnicodeDecodeError` 并使返回值为 `None`。改用文件重定向
  再以 `errors='replace'` 读取。
